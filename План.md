# Component-Driven Design Kit: Architecture & Execution Spec

## 1. Architectural Decision Record (ADR-001)

### Status

Accepted

### Context & Problem Statement

Требуется развернуть дизайн-систему (ДС) в Pixso с поддержкой токенизации, темизации и автоматизированной сборки интерактивных прототипов через LLM-агента (DeepSeek Harness). Рассматривались три пути:

1. **Figma-Kit Import:** импорт готовых `.fig` (Obra, Untitled UI).
2. **Adapter Layer:** маппинг стороннего UI-кита Pixso на кодовую базу через словарь трансляции.
3. **Component-Driven Kit (Code-to-Canvas):** детерминированная кодогенерация библиотеки в Pixso напрямую из кодовой базы компонентов (shadcn/ui на базе Tailwind v4 + Radix).

### Decision

Принят **Вариант 3 (Component-Driven Kit)**.

### Rationale & Trade-offs

```
+-----------------------------------------------------------------------------+
| ФАКТОР                 | FIGMA IMPORT        | ADAPTER         | CODE-FIRST |
+-----------------------------------------------------------------------------+
| Скорость старта        | Высокая (иллюзорная)| Средняя         | Высокая*   |
| Чистота связей токенов | 10–30% (разрывы)    | 70%             | 100%       |
| Тождество пропсов      | Случайное           | Через маппинг   | Тождество  |
| Устойчивость к LLM     | Низкая (галлюцинации| Средняя         | Абсолютная |
| Стоимость поддержки    | Высокая (ручной фикс| Средняя (2 мира)| Нулевая    |
+-----------------------------------------------------------------------------+
*При фокусе на ядре из 8 базовых компонентов (Golden Eight).

```

* **Единый источник истины (SSOT):** репозиторий кода (`globals.css` + `*.tsx` + `cva`). Отсутствует рассинхронизация между тем, что сверстано, и тем, что нарисовано.
* **Исключение деградации метаданных:** импорт `.fig` в Pixso ломает `variableAlias`, превращает переменные в сырой HEX и деформирует min/max width в Auto-layout. Генерация через API создает валидные узлы.
* **Детерминизм для LLM:** модель оперирует пропсами TypeScript/CVA (`variant`, `size`). Векторная геометрия, привязка токенов и компоновка вынесены в детерминированные рантайм-раннеры.

## 2. System Architecture & Topology

Пайплайн разделен на два изолированных файла в Pixso для соблюдения enterprise-стандарта.

```
+-----------------------------------------------------------------------------+
| REPOSITORY (Git: tokens, CVA, AST spec)                                     |
|  - globals.css                                                              |
|  - components/ui/*.tsx                                                      |
+-----------------------------------------------------------------------------+
                                      │
               [tokens:push]          │          [components:build]
                                      ▼
+-----------------------------------------------------------------------------+
| FILE 1: DS_Library.pixso (Мастер-библиотека)                                 |
|  - Collections: "Semantic" (Light/Dark Modes)                               |
|  - ComponentSets: Button, Input, Card, Checkbox, etc.                       |
|  - Output: ds-manifest.json (с экспортированными глобальными `node.key`)    |
+-----------------------------------------------------------------------------+
                                      │
                                      │ [Library Publish & Cross-file Import]
                                      ▼
+-----------------------------------------------------------------------------+
| FILE 2: App_Screens.pixso (Рабочие макеты и прототипы)                      |
|  - Instances: импортируются по `key` через `importComponentByKeyAsync()`    |
|  - Layout: сборка экранов через Auto-layout без Detach                      |
|  - Theme Switch: смена моды на контейнере в 1 клик                          |
+-----------------------------------------------------------------------------+

```

## 5. Implementation Code: Builders & Runners

### 5.1. Библиотечный генератор: `Button` ComponentSet Builder

Скрипт исполняется в `DS_Library.pixso` через Pixso MCP `eval_script`.

```javascript
(async function buildButtonSet() {
  const vars = await pixso.variables.getLocalVariablesAsync();
  const getVar = (name) => vars.find(v => v.name === name);

  const varPrimary = getVar("color/primary");
  const varPrimaryFg = getVar("color/primary-foreground");
  const varBorder = getVar("color/border");
  const varRadius = getVar("radius/default");

  const variants = ["default", "outline", "ghost", "destructive"];
  const sizes = [
    { name: "sm", h: 32, px: 12, py: 6, font: 12 },
    { name: "default", h: 36, px: 16, py: 8, font: 14 },
    { name: "lg", h: 44, px: 24, py: 10, font: 16 }
  ];

  await pixso.loadFontAsync({ family: "Inter", style: "Medium" });

  const components = [];
  let posX = 0, posY = 0;

  for (const v of variants) {
    for (const s of sizes) {
      const comp = pixso.createComponent();
      comp.name = `variant=${v}, size=${s.name}`;
      comp.layoutMode = "HORIZONTAL";
      comp.primaryAxisAlignItems = "CENTER";
      comp.counterAxisAlignItems = "CENTER";
      comp.paddingLeft = comp.paddingRight = s.px;
      comp.paddingTop = comp.paddingBottom = s.py;
      comp.resize(120, s.h);
      comp.primaryAxisSizingMode = "AUTO";
      comp.counterAxisSizingMode = "FIXED";

      if (varRadius) comp.setBoundVariable("cornerRadius", varRadius.id);

      const text = pixso.createText();
      text.name = "label";
      text.fontName = { family: "Inter", style: "Medium" };
      text.characters = "Button";
      text.fontSize = s.font;
      comp.appendChild(text);

      if (v === "default") {
        comp.fills = [{ type: "SOLID", color: { r: 0.1, g: 0.1, b: 0.1 } }];
        if (varPrimary) comp.setBoundVariable("fills", varPrimary.id);
        text.fills = [{ type: "SOLID", color: { r: 1, g: 1, b: 1 } }];
        if (varPrimaryFg) text.setBoundVariable("fills", varPrimaryFg.id);
      } else if (v === "outline") {
        comp.fills = [];
        comp.strokes = [{ type: "SOLID", color: { r: 0.8, g: 0.8, b: 0.8 } }];
        if (varBorder) comp.setBoundVariable("strokes", varBorder.id);
        comp.strokeWeight = 1;
      }

      comp.x = posX;
      comp.y = posY;
      posY += s.h + 24;
      components.push(comp);
    }
    posY = 0;
    posX += 160;
  }

  const setNode = pixso.combineAsVariants(components, pixso.currentPage);
  setNode.name = "Button";
  return { status: "SUCCESS", key: setNode.key, id: setNode.id };
})();

```

### 5.2. Рабочий раннер: Cross-File Screen Assembler

Скрипт исполняется в `App_Screens.pixso` через Pixso MCP `eval_script`. Принимает сгенерированный AST и манифест.

```javascript
(async function assembleScreen(ast, manifest) {
  const container = pixso.createFrame();
  container.name = ast.container.title;
  container.resize(ast.container.width, 10);
  container.layoutMode = ast.container.layout;
  container.primaryAxisSizingMode = "AUTO";
  container.counterAxisSizingMode = "FIXED";
  container.paddingTop = container.paddingBottom = ast.container.padding;
  container.paddingLeft = container.paddingRight = ast.container.padding;
  container.itemSpacing = ast.container.gap;

  for (const el of ast.elements) {
    const meta = manifest.components[el.component];
    if (!meta || !meta.key) continue;

    let master;
    try {
      master = await pixso.importComponentByKeyAsync(meta.key);
    } catch (err) {
      console.error(`Import failed for key ${meta.key}:`, err);
      continue;
    }

    const instance = master.createInstance();

    if (el.props && instance.setProperties) {
      instance.setProperties(el.props);
    }

    if (el.slot_text) {
      const textNode = instance.findOne(n => n.type === "TEXT");
      if (textNode) {
        await pixso.loadFontAsync(textNode.fontName);
        textNode.characters = el.slot_text;
      }
    }

    container.appendChild(instance);
    instance.layoutAlign = "STRETCH";
  }

  pixso.currentPage.selection = [container];
  pixso.viewport.scrollAndZoomIntoView([container]);
  return { status: "SUCCESS", screen_id: container.id };
})(AST_PAYLOAD, MANIFEST_PAYLOAD);

```

### 5.3. Аудит макета: Zero-Raw-Props Validator

Скрипт рекурсивно проверяет экран на наличие «сырых» цветов, пропущенных токенов и отсоединенных инстансов.

```javascript
(async function auditLayout(nodeId) {
  const root = await pixso.getNodeByIdAsync(nodeId);
  if (!root) return { error: "Node not found" };

  const violations = [];

  function walk(node) {
    if (node.type === "INSTANCE" && node.isDetached) {
      violations.push({ id: node.id, name: node.name, issue: "DETACHED_INSTANCE" });
    }

    if (node.fills && Array.isArray(node.fills)) {
      node.fills.forEach(fill => {
        if (fill.type === "SOLID" && fill.visible !== false) {
          const bound = node.boundVariables && node.boundVariables.fills;
          if (!bound) {
            violations.push({ id: node.id, name: node.name, issue: "RAW_FILL_COLOR" });
          }
        }
      });
    }

    if ("children" in node) {
      for (const child of node.children) {
        walk(child);
      }
    }
  }

  walk(root);
  return {
    valid: violations.length === 0,
    totalViolations: violations.length,
    violations: violations
  };
})(TARGET_FRAME_ID);

```

```text

TARGET SYSTEM: shadcn-pixso-core

INPUT: Natural language layout description
OUTPUT: Pure JSON matching ui-ast.schema.json

STRICT RULES:
1. OUTPUT ZERO PROSE. No explanations, no markdown fences outside of json.
2. USE ONLY registered components: Button, Input, Checkbox, Separator.
3. Props must strictly adhere to the provided ds-manifest.json. Never invent states or sizes.
4. Auto-layout hierarchy: screens MUST use a parent container with VERTICAL layout, width 360-480px, padding 24, gap 16.
5. All buttons and inputs must declare explicit slot_text or placeholders.

FAILURE TO COMPLY WITH JSON SCHEMA HALTS THE PIPELINE.
```
