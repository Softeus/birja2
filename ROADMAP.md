# Дорожная карта: код-first ДС в Pixso + LLM-сборка прототипов

Решения, принятые заказчиком (не пересматриваются без его слова):

| Решение | Значение |
|---|---|
| Источник компонентов | Код (shadcn/ui + Tailwind v4 + CVA). Готовый Figma-кит (Obra и т.п.) **не используется** |
| Источник истины | Репозиторий кода → генерируемые артефакты: `tokens.json`, `ds-manifest.json` |
| Pixso | Приёмник: токены (переменные + режимы Light/Dark), ComponentSets, макеты. Тариф **Pro** |
| Прототип | **React** (рабочая интерактивность). Нативные реакции Pixso — вне scope (API записи не подтверждён) |
| Роль LLM (DSH) | Интерпретация запроса → строгий UI-AST JSON. Геометрию и запись на холст делает детерминированный раннер |
| Репозиторий | Новый, создаётся в `D:\__Projects\birja2` (Next.js App Router + shadcn, пути из `ds-source.config.json`) |

Транспорт к Pixso: Local MCP `http://127.0.0.1:3667/mcp` (Streamable HTTP), требует открытого файла в Pixso Desktop ≥ 2.2.0 и сидена с правом редактирования.

Технические находки (важно для поддержки):
- Pixso принимает тип переменной только в нижнем регистре (`color`, `number`) — `COLOR`/`FLOAT` отклоняются.
- `setBoundVariable("fills", id)` молча не работает; цвета привязываются через `pixso.variables.setBoundVariableForPaint(paint, "color", variable)`.
- `setBoundVariable` принимает **объект** переменной, не строку id.
- Шрифтовой стиль Inter называется `Semi Bold` (не `SemiBold`).
- `resize()` сбрасывает sizing modes — их надо выставлять после resize.
- Next.js 16: динамический роут с чтением файлов требует `export const instant = false` + `generateStaticParams`.

Ограничение сети: `ui.shadcn.com` недоступен (connection reset), `registry.npmjs.org` и `raw.githubusercontent.com` доступны, поэтому `shadcn add` не работает — компоненты берутся из `github.com/shadcn-ui/ui`.

## Известные дефекты макетов (в очередь на правку)

Исправлено в этой итерации: переносы текста в инстансах (hug-текст в мастерах + правила растяжения в сборщике), обрезка длинных подписей кнопок, подпись чекбокса в строке.

Осталось:
1. **Двухколоночные поля (шаг 2).** Input в горизонтальном стеке не делит ширину пополам — фиксированные 360 px из мастера.
2. **Card в инстансе.** Лишняя высота снизу: контент карточки не пересчитывает размер при смене текста.
3. **Dialog** собран, но в макетах пока не используется — нужен отдельный AST-пример.

## Что НЕ делаем (осознанно)

- Импорт `.fig` из Figma-китов: теряет алиасы переменных и min/max автолейаута.
- Программная запись нативных prototype-реакций Pixso: не подтверждена публичным API; прототип делаем в React.
- D2C+ (design-to-code самого Pixso): требует enterprise-space, у нас Pro.
- Свободный доступ LLM к `apply_design`/`eval_script` в обычном режиме: только через валидированный AST.

## Критическая цепочка и точки отказа

1. Local MCP живёт только при открытом файле в Pixso Desktop → скрипты должны явно диагностировать это.
2. `eval_script` не откатывается при ошибке → все генераторы пишут в отдельную страницу `_generated` и сначала в `_sandbox`.
3. Порт 3667 не фиксирован → адрес берётся из настроек клиента, храним в `.env`.

## Оценка

Итого: **7–11 рабочих дней** до состояния «код → токены/компоненты в Pixso + сборка экрана и React-прототипа по AST + аудит». Фазы 0–2 — обязательный минимум, дают 80 % ценности.
