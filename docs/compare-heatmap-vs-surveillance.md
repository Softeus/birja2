# Сравнение: Heatmap vs Surveillance Desk (с проверкой фактов)

Дата: 01.11.2026. Проверено запросами к MOEX ISS в момент анализа. Прочитаны: `moex_market_heatmap_specification.md`, `moex_spread_liquidity_monitor_specification.md`, `HANDOFF-EXTERNAL.md`, `moex_llm_friendly_design_system_analysis.md`.

## 1. Проверка чужого анализа (10 утверждений)

| Утверждение | Статус | Комментарий |
|---|---|---|
| Требования спеки и правила handoff несовместимы (Sheet, Slider, Tooltip, графики) | **Верно** | В `ds-manifest.json` их нет, `HANDOFF-EXTERNAL.md` §10 перечисляет их как отсутствующие |
| `Card` не описывает вложенное содержимое | **Верно** | Слоты только `title`, `description` |
| Пороги: в тексте 0.5 / 1.5%, в коде 1 / 2% | **Верно** | `anomalyThresholdPercent = 1.0`, критический — `*2` |
| Функция не учитывает оборот и `BID > OFFER` | **Верно** | Условие «при ненулевом обороте» не проверяется |
| Односторонняя котировка → `null` → бумага исчезает из монитора | **Верно и даже мягче** | Сейчас в TQBR таких 12, без котировок — 190 из 511 |
| `DECIMALS` запрашивается, но не используется; округление до сравнения | **Верно** | `+…toFixed(3)` до проверки порога |
| Референсный код на `bg-zinc-*` нарушает токены ДС | **Верно** | Плюс `border-zinc-850` — такого цвета в Tailwind нет, класс молча не применится |
| Нет объёмов лучших заявок → OBI не вычислить | **Верно, подтверждено данными** | `BIDDEPTH`, `OFFERDEPTH`, `NUMBIDS`, `NUMOFFERS` в TQBR = `null` для всех проверенных бумаг |
| «Живой JSON получить не удалось» | **Неверно** | Работает: 200, 150–800 мс, CORS отдаёт `Access-Control-Allow-Origin`; 20 запросов подряд — без 429 |
| «При 50 параллельных запросах будет 429» | **Не проверено** | 20 последовательных прошли; лимит не воспроизведён, но пачка запросов действительно лишняя |

Чего в чужом анализе нет, а оно меняет вывод: **аномалий почти нет**. Медиана относительного спреда 0.20%, p90 — 0.87%, максимум по всему TQBR — **2.10%**. Порог спеки «критический ≥1.5%» даёт **3 бумаги** (все — префы с оборотом от десятков тысяч рублей), «≥3%» — **0**. Голубые фишки: SBER 0.020%, LKOH 0.016%, ROSN 0.052% — то есть «норма ≤0.05%» из спеки описывает только первый эшелон.

## 3. Сравнение приложений

| Критерий | Heatmap (44 плитки) | Surveillance Desk (радар + стакан) |
|---|---|---|
| Запросов к ISS для экрана | 1 срез; +3 только если нужны веса | 1 срез (+3 для весов не нужны) |
| Данные реальные | **100%** | **Площадь/спред — реальные; объёмы, глубина, OBI — синтез** |
| Доменная математика | процент изменения, форматирование | спред, OBI, генератор уровней стакана |
| Недостающие данные, которые нельзя добыть | нет | объёмы Bid/Ask (ISS их не отдаёт) |
| Хватит ли данных для сценария | да | **нет**: аномалий ≥1.5% — 3 бумаги, ≥3% — 0, максимум 2.1% |
| Визуализация | treemap: алгоритм укладки, группировка по секторам | scatter с лог-осью, лестница стакана, шкала OBI, лента |
| Новых компонентов в ДС | 3 (Sheet, Sparkline, ToggleGroup) | 6–7 (Sheet, Slider, Tooltip, Scatter, Depth, Gauge, Badge-варианты) |
| Состояний, которые надо показать | 4 (загрузка, задержка, торги закрыты, ошибка) | 6 (+ односторонняя котировка, + «данные смоделированы») |
| Объём кода | ~700–900 строк | ~1400–1800 строк |
| Срок | **3–4.5 дня** | **6–8 дней** |
| Соответствие handoff без расширения ДС | нет, но отклонение на 3 компонента | нет, отклонение на 6–7 + явный конфликт «графики нельзя» |
| Что спросят на интервью | «откуда веса и почему они на прошлый день», «что за задержка» | **«откуда объёмы в стакане?»** — и ответ «синтезированы» обнуляет доверие |
| Проверяемость фактами | полная: каждая цифра сверяется с ISS | частичная: 2 из 4 виджетов недоказуемы |
| Читаемость за 10 минут | высокая: 44 плитки, один взгляд | средняя: нужен разбор, что такое OBI |
| Нарратив для МО | «продукт для розницы» | «внутренний контроль рынка» — ближе к самой бирже |
| Риск провала демо | средний (пустые плитки, задержка) | **высокий** (пустые аномалии + поддельный стакан) |

## 4. Итог

1. **Heatmap проще, честнее и вдвое дешевле.** Всё, что видит интервьюер, вычислено из реальных данных; ни один виджет не приходится оправдывать.
2. **Surveillance сильнее по нарративу, но построен на данных, которых нет.** OBI, объёмы и глубина стакана в открытом ISS отсутствуют — это не «риск», а факт, подтверждённый полем `null`. Плюс сам сюжет «аномальных спредов» не подтверждается рынком: критических случаев 3 из 309, и это префы с мизерным оборотом.
3. **Чужой анализ методологически верен** (противоречие спеки и контракта ДС, ошибки порогов и форматирования), но опирался на документы, а не на данные: он не проверил ни доступность API, ни фактическое распределение спредов, ни заполненность полей стакана. Обе ошибки в обе стороны: API работает, но объёмов в нём нет.
4. **Если нужен нарратив «surveillance», его можно сохранить без подделок:** вместо стакана и OBI — реальные метрики качества ликвидности: относительный спред, `MINSTEP / mid × 100` (стоимость одного шага в %), спред в шагах цены, оборот, число сделок, и явная плашка «глубина стакана в ISS недоступна». Это сильнее, чем нарисованный стакан: ограничение источника, названное вслух, читается как знание рынка.
5. **Рекомендация:** heatmap как MVP (3–4.5 дня). Если нужен «внутренний контроль» — следующий шаг на том же движке: экран «качество ликвидности» с 5 реальными метриками, без стакана.

## 5. Что решить

1. Берём heatmap как MVP и не трогаем монитор, или делаем монитор без OBI/стакана (реальные метрики + честное ограничение)?
2. Кто на демо платит за разбор: 44 плитки видно сразу, монитор требует объяснения — есть ли 10 минут?
3. Pixso-экраны нужны для выбранного варианта? Для heatmap плитка — это `rect` + текст, то есть новый тип узла в AST (+2–4 дня); для монитора дополнительно нужны графики, которых в Pixso нет.
